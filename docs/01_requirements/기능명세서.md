## 2. 사용자 기능

|기능 ID|기능명|사전 조건|입력|처리 과정|정상 결과|예외 처리|
|--|--|--|--|--|--|--|
|F-01|회원가입|로그인하지 않은 상태이다.|회원 아이디, 비밀번호, 회원 이름, 이메일 주소(모두 필수)|1. 모든 항목이 입력되었는지 확인한다(Sec-005).<br>2. 회원 아이디가 영문 대/소문자, 숫자로 20자 이하인지 확인한다.<br>3. 비밀번호가 규칙에 맞는지 확인한다. 영문, 숫자, 특수문자 중 2종류 이상을 조합하면 10자 이상, 3종류 이상을 조합하면 8자 이상이어야 하고, 연속된 숫자는 사용할 수 없다. 특수문자는 `! @ # $ % ^ & *`만 사용할 수 있다.<br>4. 이메일 주소에 @가 들어 있는지 확인한다.<br>5. 이미 사용 중인 회원 아이디인지 확인한다.<br>6. 비밀번호를 해시한다(Sec-004).<br>7. 회원 정보를 저장한다.|가입 완료를 안내하고 로그인할 수 있다(UI-002).|- 입력하지 않은 항목이 있으면 어떤 항목인지 안내하고 저장하지 않는다.<br>- 아이디 형식이 맞지 않거나 이미 사용 중인 아이디이면 안내하고 저장하지 않는다.<br>- 비밀번호가 규칙에 맞지 않으면 안내하고 저장하지 않는다.<br>- 이메일 주소에 @가 없으면 안내하고 저장하지 않는다.|
|F-02|로그인|로그인하지 않은 상태이다. 가입된 회원 또는 관리자 계정이 있다.|회원 아이디, 비밀번호|1. 아이디와 비밀번호가 입력되었는지 확인한다.<br>2. 입력한 비밀번호를 해시하여 저장된 값과 비교한다(Sec-004).<br>3. 일치하면 로그인 상태로 만든다.<br>4. 비회원일 때 세션에 쌓아 둔 천장 상태가 있으면 회원의 저장된 천장 상태를 우선 사용하고, 세션의 값은 덮어쓰지 않는다. 비회원 세션의 천장 상태는 합치지 않고 버린다.|로그인되어 회원은 시뮬레이터와 재화 플래너 메뉴로, 관리자는 관리자 메뉴로 이동한다. 회원은 저장해 둔 천장 상태, 재화 계획, 기록을 사용할 수 있다.|- 아이디나 비밀번호가 비어 있으면 안내한다.<br>- 아이디 또는 비밀번호가 맞지 않으면 로그인 실패를 안내한다.|
|F-03|로그아웃|로그인한 상태이다.|로그아웃 요청|1. 로그인 상태를 해제한다.|로그아웃되어 기록·통계, 재화 계획 저장, 내 정보 화면에 접근할 수 없다(Sec-002). 시뮬레이터와 재화 플래너 계산은 계속 쓸 수 있다.|- 이미 로그아웃된 상태이면 로그인 화면으로 안내한다.|
|F-04|내 정보 조회|회원으로 로그인한 상태이다.|조회 요청|1. 로그인한 회원의 정보를 조회한다.<br>2. 비밀번호는 표시하지 않는다.|회원 아이디, 회원 이름, 이메일 주소가 표시된다.|- 로그인하지 않았으면 로그인 화면으로 안내한다(Sec-002).|
|F-05|내 정보 수정|회원으로 로그인한 상태이다.|회원 이름, 이메일 주소. 비밀번호를 바꿀 때는 기존 비밀번호와 새 비밀번호를 함께 입력한다.|1. 필수 항목이 입력되었는지 확인한다(Sec-005).<br>2. 이메일 주소에 @가 들어 있는지 확인한다.<br>3. 비밀번호를 바꾸는 경우 기존 비밀번호를 해시하여 저장된 값과 비교한다.<br>4. 일치하면 새 비밀번호가 회원가입의 비밀번호 규칙에 맞는지 확인하고 해시하여 저장한다(Sec-004).<br>5. 변경한 정보를 저장한다. 비밀번호를 바꾸지 않으면 기존 비밀번호가 유지된다.|수정 완료를 안내하고 변경된 정보가 반영된다(UI-002).|- 회원 아이디는 수정할 수 없다.<br>- 기존 비밀번호가 맞지 않으면 비밀번호를 변경하지 않고 안내한다.<br>- 새 비밀번호가 규칙에 맞지 않거나 이메일 주소에 @가 없으면 안내하고 저장하지 않는다.<br>- 필수 항목이 비어 있으면 안내하고 저장하지 않는다.|
|F-06|회원 탈퇴|회원으로 로그인한 상태이다. 관리자 계정은 탈퇴할 수 없다.|탈퇴 요청, 탈퇴 확인 응답(비밀번호는 다시 입력받지 않는다)|1. 한 번 더 탈퇴 여부를 확인한다(UI-003).<br>2. 확인하면 해당 회원의 천장 상태, 재화 계획, 시뮬레이션 기록을 삭제한다.<br>3. 회원 정보를 완전히 삭제한다(Data-004).<br>4. 로그인 상태를 해제한다.|탈퇴 완료를 안내하고 첫 화면으로 이동한다. 삭제된 데이터는 복구할 수 없다.|- 확인 단계에서 취소하면 탈퇴하지 않는다.<br>- 관리자 계정은 탈퇴할 수 없다고 안내한다.|

|F-07|게임·배너 선택|게임과 배너가 등록되어 있다. 로그인은 필요 없다(UI-001).|게임, 배너|1. 등록된 게임 목록을 보여 주고 게임을 선택받는다.<br>2. 선택한 게임의 배너 목록을 보여 준다. 관리자가 반영한 배너만 보인다(Admin-009).<br>3. 배너를 선택받는다.<br>4. 선택한 배너의 종류, 픽업 캐릭터, 확률 규칙, 현재 천장 상태를 불러온다.|선택한 배너의 정보(이름, 종류, 픽업 캐릭터, 천장 횟수)와 현재 천장 상태가 표시되고 뽑기를 시작할 수 있다.|- 등록된 게임이나 배너가 없으면 없다고 안내한다.<br>- 규칙이 등록되지 않은 배너는 뽑기를 할 수 없다고 안내한다.<br>- 아직 시작하지 않은 예정 배너도 선택할 수 있다.|
|F-08|1회 뽑기|배너를 선택한 상태이다.|뽑기 방식(F-13 자유 뽑기 또는 F-14 내 재화로 뽑기), 1회 뽑기 요청|1. 선택한 배너의 현재 천장 상태를 가져온다.<br>2. 확률 규칙을 적용해(F-10, F-11) 등급과 캐릭터를 정한다.<br>3. 천장 상태를 갱신한다.<br>4. 내 재화로 뽑기이면 재화를 소모한다.<br>5. 로그인한 회원이면 결과를 저장한다(F-16, F-36).|결과로 나온 캐릭터의 이름, 등급, 픽업 캐릭터 여부가 표시된다. 갱신된 천장 횟수와 누적 뽑기 횟수가 표시된다.|- 배너를 선택하지 않았으면 선택하도록 안내한다.<br>- 내 재화로 뽑기에서 재화가 부족하면 뽑기를 하지 않고 안내한다(F-14).|
|F-09|10회 뽑기|배너를 선택한 상태이다.|뽑기 방식, 10회 뽑기 요청|1. 1회 뽑기(F-08)와 같은 처리를 10번 순서대로 한다. 매번 천장 상태를 갱신한다.<br>2. 내 재화로 뽑기이면 10회분 재화가 있는지 먼저 확인한다.<br>3. 10번의 결과를 한 번의 기록으로 묶는다(F-36).|10번의 결과가 한 번에 모여서 표시된다. 갱신된 천장 횟수와 누적 뽑기 횟수가 표시된다.|- 배너를 선택하지 않았으면 선택하도록 안내한다.<br>- 내 재화로 뽑기에서 10회분 재화가 없으면 뽑기를 하지 않고 안내한다. 10회분보다 적게 남았을 때 가능한 횟수만 뽑게 하지는 않는다.|
|F-10|천장·픽업 확률 적용|배너에 확률 규칙이 등록되어 있다(Admin-003).|배너, 현재 천장 상태|1. 배너가 속한 게임의 확률 규칙을 가져온다(Data-001).<br>2. 등급별 기본 확률과 천장 규칙(연속으로 나오지 않았을 때 올라가는 확률)으로 이번 뽑기의 등급별 확률을 구한다.<br>3. 난수로 등급을 정한다.<br>4. 최고 등급이면 픽업 캐릭터가 나올 확률 규칙으로 픽업 캐릭터인지 정하고, 정해진 캐릭터를 고른다.<br>5. 게임 이름에 따라 나누는 조건문 없이 규칙 데이터만으로 처리한다(SYS-004). 데이터로 표현할 수 없는 규칙만 따로 분리해서 구현한다.|뽑기 1회마다 규칙에 맞는 등급과 캐릭터가 정해진다. 천장 횟수에 도달하면 규칙대로 최고 등급이 나오거나 확률이 올라간다.|- 확률 규칙이 없거나 확률의 합이 100%가 아니면 뽑기를 하지 않고 안내한다.<br>- 픽업 캐릭터가 등록되지 않은 배너이면 픽업 없이 등급까지만 정한다.|
|F-11|배너 종류별 천장 이어짐 적용|게임에 배너 종류별 천장 이어짐 규칙이 등록되어 있다(Admin-003).|배너|1. 선택한 배너의 종류가 속한 천장 묶음(같은 천장을 이어서 쓰는 배너 종류들)을 규칙 데이터에서 찾는다.<br>2. 같은 묶음의 배너끼리는 천장 횟수를 공유하고, 다른 묶음은 따로 센다.<br>3. 뽑을 때마다 해당 묶음의 천장 상태를 갱신한다.<br>4. 어떤 종류끼리 이어지는지는 게임별 규칙 데이터를 따른다(C4).|같은 묶음의 다른 배너로 바꿔도 천장 횟수가 이어진다. 다른 묶음의 배너는 따로 센다.|- 이어짐 규칙이 없는 게임이면 배너마다 따로 센다.|
|F-12|시작 상태 설정|배너를 선택한 상태이다.|현재 천장 횟수, 픽업 확정 여부(해당 게임에 그런 규칙이 있을 때만)|1. 현재 천장 횟수가 0 이상이고 해당 배너의 천장 횟수보다 작은지 확인한다(Sec-005).<br>2. 픽업 확정 여부는 게임 규칙에 있을 때만 입력받는다.<br>3. 입력한 값으로 해당 천장 묶음의 천장 상태를 정한다.|설정한 상태가 천장 상태로 정해지고 이후 뽑기가 그 상태에서 시작된다(UI-002).|- 천장 횟수가 0보다 작거나 천장 횟수 이상이거나 숫자가 아니면 안내하고 설정하지 않는다.<br>- 픽업 확정 규칙이 없는 게임이면 확정 여부 항목을 보이지 않는다.|
|F-13|자유 뽑기|배너를 선택한 상태이다.|자유 뽑기 선택, 뽑기 횟수(1회 또는 10회)|1. 재화를 확인하거나 소모하지 않고 뽑기(F-08, F-09)를 한다.<br>2. 뽑은 횟수를 누적한다.|횟수 제한 없이 뽑을 수 있고 지금까지 뽑은 횟수가 누적되어 표시된다.|- 해당 없음(재화 제한이 없다).|
|F-14|내 재화로 뽑기|배너를 선택한 상태이다.|내 재화로 뽑기 선택, 보유 재화(재화 종류별 수량)|1. 재화 수량이 0 이상의 숫자인지 확인한다(Sec-005).<br>2. 게임의 환산 비율(Data-001)로 뽑을 수 있는 횟수를 구한다.<br>3. 뽑을 때마다 재화를 소모하고 남은 재화를 갱신한다.|뽑은 횟수만큼 재화가 줄고 남은 재화와 남은 뽑기 횟수가 표시된다.|- 재화가 0 미만이거나 숫자가 아니면 안내한다.<br>- 재화가 부족하면 뽑기를 할 수 없다고 안내한다.|
|F-15|비회원 천장 상태 유지|로그인하지 않은 상태에서 뽑기를 했다.|-|1. 뽑을 때마다 게임별, 천장 묶음별 천장 상태를 브라우저 세션에 저장한다.<br>2. 같은 브라우저에서 시뮬레이터를 다시 열면 세션의 천장 상태를 불러온다.<br>3. 데이터베이스에는 저장하지 않는다(Data-003).|같은 브라우저에서 이어서 사용할 수 있다. 브라우저를 닫으면 사라진다.|- 세션이 만료되었으면 천장 상태가 처음(0회)으로 시작한다는 점을 안내한다.|
|F-16|회원 천장 상태 저장·불러오기|회원으로 로그인한 상태이다.|-|1. 뽑을 때마다 게임별, 천장 묶음별 천장 상태를 로그인한 회원과 연결하여 저장한다(Data-003).<br>2. 시뮬레이터를 열면 회원의 저장된 천장 상태를 불러온다.<br>3. 본인의 데이터만 사용한다(Sec-001).|로그아웃하거나 브라우저를 닫은 뒤 다시 로그인해도 이어서 사용할 수 있다.|- 저장된 천장 상태가 없으면 처음(0회)부터 시작한다.<br>- 저장에 실패하면 실패를 안내하고 이번 뽑기 결과는 화면에 그대로 보여 준다.|
|F-17|뽑기 결과 이미지 표시|뽑기 결과가 나온 상태이다.|-|1. 결과 캐릭터의 이미지 위치 정보를 가져온다(Data-005).<br>2. 이름, 등급과 함께 이미지로 보여 준다.<br>3. 이미지가 없거나 불러오지 못하면 이름, 등급을 글자로 보여 주고 기본 이미지를 보여 준다(UI-006).<br>4. 이미지의 저작권과 비공식 프로젝트 안내를 볼 수 있는 위치에 둔다(UI-007).|결과 캐릭터가 이미지와 함께 표시된다.|- 이미지를 불러오지 못해도 글자와 기본 이미지로 계속 사용할 수 있다.|

|F-18|획득 확률 계산|게임과 배너에 확률 규칙이 등록되어 있다. 로그인은 필요 없다(UI-001).|게임, 배너, 현재 천장 횟수, 픽업 확정 여부(해당 게임에 규칙이 있을 때), 뽑을 수 있는 횟수|1. 입력값을 확인한다(Sec-005). 천장 횟수는 0 이상이고 천장 횟수보다 작아야 하며, 뽑을 수 있는 횟수는 0 이상의 숫자여야 한다.<br>2. 게임의 확률 규칙을 가져온다(F-10과 같은 규칙 데이터).<br>3. 천장 횟수와 확정 여부를 상태로 하여, 뽑기 횟수만큼 상태가 바뀌는 확률을 규칙에 따라 계산한다(시뮬레이션을 반복해서 어림잡지 않는다).<br>4. 목표 픽업 캐릭터를 한 번이라도 얻을 확률을 구한다.|목표 픽업 캐릭터를 얻을 확률이 퍼센트로 표시된다.|- 입력값이 올바르지 않으면 어떤 항목이 잘못되었는지 안내하고 계산하지 않는다(UI-002).<br>- 확률 규칙이 없는 배너이면 계산할 수 없다고 안내한다.<br>- 목표는 배너의 픽업 캐릭터 중 사용자가 고른 1명 이상이다. 픽업 캐릭터별 확률은 배너 종류에 따른 게임의 공식 확률 규칙(Admin-002, Admin-003)을 따른다.|

|F-21|목표 배너·날짜 선택|게임을 선택한 상태이다.|목표 배너, 목표 날짜 기준(배너 시작일 또는 배너 종료일)|1. 게임의 배너 목록을 보여 준다. 이미 시작한 배너와 앞으로 열릴 예정인 배너를 모두 보여 준다.<br>2. 중국 서버 일정을 한국 서버 일정으로 바꾼 배너도 포함한다. 일정은 배너마다 따로 둔 한국 서버 일정을 사용한다(Plan-006, Data-002).<br>3. 목표 날짜의 기본은 선택한 배너의 시작일이고 사용자가 종료일까지로 바꿀 수 있다.<br>4. 오늘부터 목표 날짜까지를 계산 기간으로 정한다.|목표 배너와 목표 날짜, 그리고 오늘부터 목표 날짜까지의 계산 기간이 표시된다.|- 선택할 배너가 없으면 없다고 안내한다.<br>- 목표 날짜가 오늘보다 이전이면 계산 기간이 없다고 안내하고 0일로 계산한다.|
|F-22|정기 수입 합산|목표 날짜가 정해졌다(F-21). 합산 항목에서 정기 수입이 선택되어 있다(F-26).|계산 기간(오늘~목표 날짜)|1. 게임의 정기 수입 데이터(재화 종류, 수량, 주기, 적용 기간)를 가져온다.<br>2. 계산 기간 안에서 각 정기 수입이 몇 번 들어오는지 날짜 기준으로 센다.<br>3. 재화 종류별로 합산한다.|재화 종류별 정기 수입 합계가 표시된다.|- 정기 수입 데이터가 없으면 0으로 계산하고 안내한다.<br>- 정기 수입을 제외하도록 선택했으면 합산하지 않는다.|
|F-23|이벤트 보상 합산|목표 날짜가 정해졌다(F-21). 합산 항목에서 이벤트 보상이 선택되어 있다(F-26).|계산 기간(오늘~목표 날짜)|1. 게임의 이벤트 데이터에서 한국 서버 일정 기준으로 계산 기간 안에 열리는 이벤트를 찾는다(Plan-006).<br>2. 목표 날짜 안에 끝나는 이벤트의 보상만 포함한다.<br>3. 재화 종류별로 합산한다.<br>4. 각 이벤트의 일정이 확정인지 예상인지 함께 표시한다(F-25).|재화 종류별 이벤트 보상 합계와 포함한 이벤트 목록이 표시된다.|- 해당 기간의 이벤트가 없으면 0으로 계산하고 안내한다.<br>- 이벤트 보상을 제외하도록 선택했으면 합산하지 않는다.<br>- 사용자는 이벤트마다 포함 여부를 고를 수 있고, 제외한 이벤트의 보상은 합산하지 않는다.|
|F-24|뽑기 횟수 환산|보유 재화와 합산 결과가 있다.|(F-20, F-22, F-23, F-27, F-28의 결과)|1. 보유 재화, 정기 수입, 이벤트 보상, 선택한 패키지와 오리지늄을 재화 종류별로 합친다.<br>2. 게임의 환산 비율(Data-001)로 뽑기 횟수로 바꾼다. 명일방주는 합성옥 600개가 1회, 오리지늄 1개가 합성옥 180개이다(위키로 최종 확인).<br>3. 뽑기로 바꾸고 남는 재화를 구한다.|합친 재화와 뽑을 수 있는 횟수, 남는 재화가 표시된다.|- 환산 비율이 등록되지 않은 재화는 환산하지 못한다고 안내한다.|
|F-25|일정 확정·예상 구분 표시|배너, 이벤트, 패키지 일정이 화면에 표시된다.|-|1. 각 일정의 확정 여부(한국 서버에서 확정, 중국 서버 기준 예상)를 가져온다(Data-002).<br>2. 확정과 예상을 구분해서 표시한다.<br>3. 예상 일정이 있으면 한국 서버의 사정으로 바뀔 수 있다는 안내를 함께 표시한다.|배너, 이벤트, 패키지마다 확정인지 예상인지 보이고, 예상 일정에는 변경될 수 있다는 안내가 보인다.|- 확정 여부가 정해지지 않은 일정은 예상으로 표시한다.|
|F-26|합산 항목 선택|목표 배너를 선택했다(F-21).|정기 수입, 이벤트 보상, 패키지의 포함 여부(각각 선택)|1. 항목별 포함 여부를 입력받는다. 기본은 정기 수입과 이벤트 보상을 포함하고 패키지는 포함하지 않는다(F-29).<br>2. 항목을 바꾸면 선택한 항목만 합산해서 결과를 다시 계산한다.|항목을 바꾸면 결과가 바로 바뀐다.|- 모든 항목을 제외하면 보유 재화만으로 계산한다.<br>- 이벤트 보상과 패키지는 이벤트·패키지마다 포함 여부를 고를 수 있다. 계산 기준 날짜는 목표 날짜 하나이다.|
|F-27|패키지 선택|게임에 패키지가 등록되어 있다.|패키지 종류, 개수|1. 계산 기간 안에 판매하는 패키지를 기간 한정과 상시로 나누어 보여 준다. 이벤트에서 판매하는 패키지는 해당 이벤트 기간에 맞춰 보여 준다.<br>2. 종류와 개수를 입력받는다.<br>3. 개수가 구매 횟수 제한 이내인지 확인한다(Sec-005).<br>4. 선택한 패키지의 구성 재화를 합산에 포함한다.|선택한 패키지와 개수, 그 패키지가 주는 재화가 표시되고 합산에 반영된다.|- 구매 횟수 제한을 넘는 개수는 선택할 수 없다고 안내한다.<br>- 개수가 0 미만이거나 숫자가 아니면 안내한다.<br>- 판매하는 패키지가 없으면 없다고 안내한다.|
|F-28|오리지늄 구매 선택|게임에 오리지늄 판매 구간이 등록되어 있다.|오리지늄 금액 구간(종류), 구매 횟수|1. 금액 구간별 오리지늄 판매 정보를 보여 준다. 오리지늄은 항상 판매하는 상품으로 취급한다.<br>2. 구간과 구매 횟수를 입력받는다.<br>3. 구매 횟수가 0 이상의 정수인지 확인한다(Sec-005).<br>4. 얻는 오리지늄을 환산 비율로 뽑기 횟수에 포함한다(F-24).|선택한 구간과 횟수, 얻는 오리지늄이 표시되고 합산에 반영된다.|- 횟수가 0 미만이거나 숫자가 아니면 안내한다.<br>- 판매 구간이 없으면 없다고 안내한다.|
|F-29|무과금 기준 기본 계산|재화 플래너 화면에 처음 들어왔다.|-|1. 패키지와 오리지늄을 선택하지 않은 상태로 시작한다(UI-005).<br>2. 보유 재화, 정기 수입, 이벤트 보상만으로 뽑기 횟수를 계산한다.<br>3. 구매를 권하는 문구는 표시하지 않는다.|무과금 기준의 뽑기 횟수가 기본 결과로 표시된다.|- 해당 없음.|
|F-30|포함 시 증가량 비교|패키지 또는 오리지늄을 하나 이상 선택했다(F-27, F-28).|-|1. 무과금 결과(F-29)와 선택을 포함한 결과를 각각 계산한다.<br>2. 두 결과를 나란히 보여 준다.<br>3. 포함해서 늘어나는 뽑기 횟수를 구한다.<br>4. 구매를 권하는 것이 아니라 차이를 보여 주는 용도임을 유지한다(UI-005).|무과금 결과, 포함한 결과, 늘어나는 뽑기 횟수가 나란히 표시된다.|- 선택한 패키지와 오리지늄이 없으면 비교를 보여 주지 않는다.|
|F-31|플래너 획득 확률 확인|뽑기 횟수가 계산되었다(F-24). 목표 배너가 선택되어 있다.|현재 천장 횟수, 픽업 확정 여부|1. 입력값을 확인한다(Sec-005).<br>2. 무과금 결과의 뽑기 횟수로 획득 확률 계산(F-18)과 같은 규칙으로 확률을 구한다.<br>3. 패키지·오리지늄을 포함한 결과의 뽑기 횟수로도 확률을 구한다.|목표 픽업 캐릭터를 얻을 확률이 무과금 결과와 포함한 결과로 각각 표시된다.|- 현재 천장 횟수가 올바르지 않으면 안내하고 계산하지 않는다.<br>- 뽑기 횟수가 0이면 확률 0%로 표시한다.|
|F-32|재화 계획 저장|회원으로 로그인한 상태이다. 재화 플래너에서 계산한 결과가 있다.|계획 이름(선택)|1. 로그인한 회원인지 확인한다(Sec-002).<br>2. 게임, 목표 배너, 입력한 보유 재화, 계산에 포함한 항목, 선택한 패키지와 오리지늄(종류, 개수)을 회원과 연결하여 저장한다(Data-003).|저장 완료를 안내하고 저장한 계획을 다시 볼 수 있다(UI-002).|- 비회원이면 저장할 수 없다고 안내하고 로그인 화면으로 안내한다.<br>- 저장에 실패하면 실패를 안내한다.|
|F-33|저장한 재화 계획 목록 조회|회원으로 로그인한 상태이다.|조회 요청|1. 로그인한 회원의 저장한 재화 계획만 조회한다(Sec-001).<br>2. 최근에 저장한 것부터 정렬한다.|저장한 계획이 목록으로 표시된다.|- 저장한 계획이 없으면 없다고 안내한다(UI-004).<br>- 로그인하지 않았으면 로그인 화면으로 안내한다(Sec-002).|
|F-34|저장한 재화 계획 불러오기|회원으로 로그인한 상태이고 저장한 계획이 있다.|목록에서 선택한 계획|1. 본인이 저장한 계획인지 확인한다(Sec-001).<br>2. 저장한 내용(게임, 목표 배너, 보유 재화, 포함 항목, 패키지·오리지늄)을 재화 플래너에 채운다.<br>3. 저장한 것은 입력값뿐이므로 최신 일정과 데이터로 다시 계산해서 보여 준다.|저장한 내용이 재화 플래너에 채워져 표시된다.|- 다른 회원의 계획이거나 없는 계획이면 접근할 수 없다고 안내한다.<br>- 저장한 목표 배너나 패키지가 이후 삭제되었으면 해당 항목은 불러오지 못한다고 안내한다.|
|F-35|배너·재화 이미지 표시|재화 플래너에 배너와 재화가 표시된다.|-|1. 배너와 재화의 이미지 위치 정보를 가져온다(Data-005).<br>2. 이름과 함께 이미지로 보여 준다.<br>3. 이미지가 없거나 불러오지 못하면 글자로 보여 주고 기본 이미지를 보여 준다(UI-006).<br>4. 저작권과 비공식 프로젝트 안내를 볼 수 있는 위치에 둔다(UI-007).|목표 배너와 재화가 이미지와 함께 표시된다.|- 이미지를 불러오지 못해도 글자와 기본 이미지로 계속 사용할 수 있다.|

|F-39|최고 등급 평균 횟수 조회|회원으로 로그인한 상태이다.|게임, 배너 종류|1. 로그인한 회원의 기록 중 선택한 게임과 배너 종류의 기록을 모은다.<br>2. 게임의 등급 체계에서 최고 등급을 정한다(Data-001).<br>3. 최고 등급이 한 번 나올 때까지 뽑은 횟수를 구해서 평균을 낸다.|최고 등급이 평균 몇 회 만에 나왔는지 게임과 배너 종류별로 표시된다.|- 최고 등급이 나온 기록이 없거나 기록이 너무 적으면 통계를 낼 수 없다고 안내한다.|
|F-58|시뮬레이션 기록 삭제|회원으로 로그인한 상태이고 기록이 있다.|삭제할 기록, 삭제 확인 응답|1. 본인의 기록인지 확인한다(Sec-001).<br>2. 한 번 더 삭제 여부를 확인한다(UI-003).<br>3. 확인하면 해당 기록을 삭제한다.|삭제 완료를 안내하고 목록에서 사라진다. 삭제한 기록은 통계(F-39, F-40)에서도 빠지며 복구할 수 없다(UI-002).|- 확인 단계에서 취소하면 삭제하지 않는다.<br>- 다른 회원의 기록이거나 없는 기록이면 접근할 수 없다고 안내한다.|
|F-40|설정 확률과 실제 결과 비교|회원으로 로그인한 상태이다.|게임, 배너 종류|1. 로그인한 회원의 기록으로 등급별 실제 비율을 계산한다.<br>2. 게임의 확률 규칙에 설정된 등급별 확률을 가져온다.<br>3. 두 값을 표와 그래프(Chart.js)로 나란히 보여 준다(SYS-001).<br>4. 뽑은 횟수가 적으면 실제 비율이 설정 확률과 많이 다를 수 있다는 점을 안내한다.|등급별 실제 비율과 설정 확률이 표와 그래프로 표시된다.|- 기록이 없으면 없다고 안내한다(UI-004).<br>- 뽑은 횟수가 적으면 차이가 클 수 있다고 함께 안내한다.|

## 7. 관리자 기능

> 관리자 항목의 삭제는 다른 데이터와 연결되지 않은 항목만 할 수 있다. 연결된 데이터(예: 뽑기 기록이 있는 배너, 회원이 저장한 계획에 쓰인 패키지)가 있는 항목은 삭제하지 않고 사용하지 않음(비활성)으로 바꾸며, 비활성 항목은 사용자 화면에 나타나지 않는다. 삭제는 실행 전에 한 번 더 확인을 받는다(UI-003). 이 규칙은 F-41~F-49의 수정 기능에 함께 적용한다.

|--|--|--|--|--|--|--|
|F-41|게임 등록·수정|관리자로 로그인한 상태이다.|게임 이름, 서버 구분(한국, 중국), 그 밖의 게임 기본 정보|1. 관리자인지 확인한다(Sec-003).<br>2. 필수 항목이 입력되었는지 확인한다(Sec-005).<br>3. 같은 이름의 게임이 이미 있는지 확인한다.<br>4. 게임 정보를 저장한다(Data-001).|등록 또는 수정 완료를 안내하고 게임 목록에 반영된다(UI-002). 이 데이터가 있으면 프로그램을 고치지 않고 새 게임을 추가할 수 있다(C4).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 필수 항목이 비어 있거나 이미 있는 게임 이름이면 안내하고 저장하지 않는다.|
|F-42|게임 설정(재화·환산 비율·등급) 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|재화 종류(이름), 재화 환산 비율(재화 간, 뽑기 1회당 재화 수량), 등급 체계(등급 이름, 순서)|1. 관리자인지 확인한다(Sec-003).<br>2. 환산 비율이 0보다 큰 숫자인지 확인한다(Sec-005).<br>3. 게임과 연결하여 저장한다(Data-001).|등록 또는 수정 완료를 안내하고 재화 플래너와 시뮬레이터에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 환산 비율이 0 이하이거나 숫자가 아니면 안내하고 저장하지 않는다.|
|F-43|배너 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|배너 이름, 배너 종류, 서버별 시작일·종료일, 일정 확정 여부(확정/예상)|1. 관리자인지 확인한다(Sec-003).<br>2. 필수 항목이 입력되었는지 확인한다.<br>3. 시작일이 종료일보다 늦지 않은지 확인한다(Sec-005).<br>4. 서버(한국, 중국)를 구분하고 한국 서버 일정을 따로 저장한다(Data-002).|등록 또는 수정 완료를 안내하고 시뮬레이터와 재화 플래너의 배너 목록에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 시작일이 종료일보다 늦거나 필수 항목이 비어 있으면 안내하고 저장하지 않는다.|
|F-44|배너 픽업 캐릭터 등록·수정|관리자로 로그인한 상태이고 배너가 등록되어 있다.|배너, 픽업 캐릭터, 캐릭터 등급, 픽업 비율|1. 관리자인지 확인한다(Sec-003).<br>2. 캐릭터가 게임에 등록되어 있는지 확인한다. 캐릭터 기본 정보는 가져오기(F-50, F-51)로 채울 수 있으며 배너의 픽업 캐릭터는 관리자가 직접 입력한다.<br>3. 픽업 비율이 0 이상 100 이하인지 확인한다(Sec-005).<br>4. 배너와 연결하여 저장한다.|등록 또는 수정 완료를 안내하고 뽑기 확률 적용(F-10)에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 등록되지 않은 캐릭터이거나 픽업 비율이 범위를 벗어나면 안내하고 저장하지 않는다.|
|F-45|확률·천장 규칙 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|등급별 기본 확률, 천장이 시작되는 횟수, 이후 올라가는 확률, 확률이 100%가 되는 횟수, 픽업 캐릭터가 나올 비율, 배너 종류별 천장 이어짐 여부|1. 관리자인지 확인한다(Sec-003).<br>2. 확률이 0 이상 100 이하이고 등급별 확률의 합이 100%인지 확인한다(Sec-005).<br>3. 규칙은 위키로 확인한 값을 입력한다.<br>4. 게임과 연결하여 저장한다(Data-001).|등록 또는 수정 완료를 안내하고 시뮬레이터(F-10, F-11)와 확률 계산(F-18, F-19)에 같이 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 확률이 범위를 벗어나거나 합이 100%가 아니면 안내하고 저장하지 않는다.|
|F-46|정기 수입 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|재화 종류, 수량, 주기(매일, 매주, 매월 등), 적용 기간|1. 관리자인지 확인한다(Sec-003).<br>2. 수량이 0 이상의 숫자인지, 적용 시작일이 종료일보다 늦지 않은지 확인한다(Sec-005).<br>3. 게임과 연결하여 저장한다(Data-001).|등록 또는 수정 완료를 안내하고 정기 수입 합산(F-22)에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 수량이 올바르지 않거나 기간이 올바르지 않으면 안내하고 저장하지 않는다.|
|F-47|이벤트·이벤트 보상 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|이벤트 이름, 한국 서버 기간, 중국 서버 기간(참고용), 일정 확정 여부, 보상 재화의 종류와 수량|1. 관리자인지 확인한다(Sec-003).<br>2. 기간의 시작일이 종료일보다 늦지 않은지, 보상 수량이 0 이상인지 확인한다(Sec-005).<br>3. 서버를 구분하고 한국 서버 일정을 따로 저장한다(Data-002).<br>4. 보상을 이벤트와 연결하여 저장한다.|등록 또는 수정 완료를 안내하고 이벤트 보상 합산(F-23)에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 기간이나 수량이 올바르지 않으면 안내하고 저장하지 않는다.|
|F-48|패키지 등록·수정|관리자로 로그인한 상태이고 게임이 등록되어 있다.|패키지 이름, 구분(기간 한정/상시), 판매 기간, 금액, 구성 재화(종류, 수량), 구매 횟수 제한|1. 관리자인지 확인한다(Sec-003).<br>2. 기간 한정이면 판매 기간이 있고 시작일이 종료일보다 늦지 않은지 확인한다(Sec-005).<br>3. 금액과 수량이 0 이상의 숫자인지 확인한다.<br>4. 서버를 구분하고 한국 서버 일정과 확정 여부를 저장한다(Data-002).|등록 또는 수정 완료를 안내하고 패키지 선택(F-27)에 반영된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 기간이나 금액, 수량이 올바르지 않으면 안내하고 저장하지 않는다.|

|F-50|게임 데이터 파일 가져오기|관리자로 로그인한 상태이고 가져올 데이터 파일(JSON)이 있다.|데이터 파일(JSON)|1. 관리자인지 확인한다(Sec-003).<br>2. 파일 형식(JSON)과 필요한 항목이 올바른지 확인한다(Sec-005).<br>3. 이미 있는 캐릭터와 배너는 갱신하고, 없는 것은 새로 추가한다.<br>4. 추가한 건수와 갱신한 건수를 센다.|가져오기 완료를 안내하고 추가한 건수와 갱신한 건수가 표시된다(UI-002). 자동 가져오기(F-51)가 되지 않을 때 대안으로 쓴다.|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 파일 형식이 올바르지 않으면 안내하고 아무것도 반영하지 않는다.<br>- 처리 중 오류가 나면 이미 처리한 내용은 되돌리고 안내한다.|

|F-52|가져온 내용 목록 확인|관리자로 로그인한 상태이다.|조회 요청|1. 관리자인지 확인한다(Sec-003).<br>2. 확인을 기다리는 가져온 내용을 조회한다.<br>3. 새로 생긴 것과 바뀐 것을 구분하고, 바뀐 것은 이전 값과 함께 보여 준다.|새로 생긴 것과 바뀐 것이 목록으로 표시된다.|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 확인할 내용이 없으면 없다고 안내한다(UI-004).|
|F-53|가져온 내용 반영·제외|관리자로 로그인한 상태이고 확인을 기다리는 내용이 있다.|항목별 반영 또는 제외 선택|1. 관리자인지 확인한다(Sec-003).<br>2. 반영하기로 한 항목을 게임 데이터에 반영한다. 이미 있는 항목은 갱신하고 없는 항목은 추가한다.<br>3. 제외하기로 한 항목은 반영하지 않는다.<br>4. 처리한 항목은 확인 대기 목록에서 없앤다.|반영한 항목이 시뮬레이터와 재화 플래너에서 바로 사용할 수 있게 되고 처리 결과를 안내한다(UI-002). 반영하기 전에는 사용자 화면에 나타나지 않는다.|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 반영 중 오류가 나면 해당 항목은 반영하지 않고 안내한다.|
|F-54|이미지 등록|관리자로 로그인한 상태이고 이미지를 연결할 캐릭터, 배너 또는 재화가 있다.|연결 대상(캐릭터, 배너, 재화), 이미지 파일 또는 이미지 위치|1. 관리자인지 확인한다(Sec-003).<br>2. 이미지 파일 형식(.jpg, .png 등)이 올바른지 확인한다(Sec-005).<br>3. 이미지의 위치 정보를 대상과 연결하여 저장한다(Data-005). 이미지 파일은 저작권 때문에 공개 저장소에 올리지 않는다.|등록 완료를 안내하고 시뮬레이터와 재화 플래너에서 이미지로 표시된다(UI-002).|- 관리자가 아니면 접근할 수 없다고 안내한다.<br>- 이미지 형식이 올바르지 않으면 안내하고 저장하지 않는다.<br>- 이미지 파일은 서버의 별도 폴더에 저장하고 DB에는 파일 위치만 저장한다.|

## 8. 계정연동 기능

|기능 ID|기능명|사전 조건|입력|처리 과정|정상 결과|예외 처리|
|--|--|--|--|--|--|--|
|F-55|비공식 연동 경고 확인|회원으로 로그인한 상태이고 계정 연동을 시작하려 한다.|안내 확인 응답|1. 계정 연동은 게임사가 공식으로 제공하는 방법이 아니어서 약관 위험이 있고 갑자기 막힐 수 있는 "실험적 기능"임을 연동을 시작하기 전에 안내한다.<br>2. 회원이 안내를 확인했는지 받는다.|안내를 확인한 회원만 연동(F-56)을 진행할 수 있다.|- 안내를 확인하지 않으면 연동을 진행하지 않는다. 직접 입력으로 계속 사용할 수 있다(F-57).<br>- 안내를 확인하는 방식은 체크 표시 동의이다.|
|F-56|게임 계정 연동·재화 가져오기|회원으로 로그인한 상태이고 비공식 연동 경고를 확인했다(F-55). 해당 게임에 연동 방법이 있다.|게임 계정 인증에 필요한 정보(명일방주는 요스타 이메일 인증)|1. 로그인한 회원인지 확인한다(Sec-002).<br>2. 연동 방식에 맞는 방법으로 게임 계정을 인증한다. 인증 정보는 저장하지 않는다(Sec-006).<br>3. 보유 재화(오리지늄, 합성옥, 헤드헌팅권 등)를 가져온다.<br>4. 가져온 값을 재화 플래너의 보유 재화 입력 항목에 채운다(F-20).|보유 재화가 자동으로 채워지고 사용자가 수정할 수 있다.|- 연동에 실패하면 실패했다는 사실을 안내하고 직접 입력하게 한다(F-57, UI-002).<br>- 연동 방법이 없는 게임이면 연동할 수 없다고 안내한다.<br>- 로그인하지 않았으면 로그인 화면으로 안내한다(Sec-002).<br>- 인증 정보는 연동 요청을 처리하는 동안 메모리에서만 사용하고 요청이 끝나면 버린다. 별도 연동 서버를 거치더라도 같다(Sec-006).|
|F-57|연동 없이 직접 입력|시뮬레이터 또는 재화 플래너를 사용한다. 로그인은 필요 없다.|보유 재화(F-20)|1. 계정 연동 없이도 시뮬레이터와 재화 플래너의 모든 기능을 사용할 수 있게 한다(C5).<br>2. 연동에 실패했거나 연동 방법이 없는 게임이면 직접 입력 화면을 그대로 보여 준다.|계정을 연동하지 않아도 재화를 직접 입력해서 모든 기능을 사용할 수 있다.|- 연동에 실패한 경우 실패했다는 사실을 함께 안내한다(UI-002).|
