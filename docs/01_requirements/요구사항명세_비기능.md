## 2. 보안

|요구사항분류|요구사항 ID|요구사항명|요구사항 상세|근거|관련 요구사항|
|--|--|--|--|--|--|
|보안|Sec-001|본인 데이터만 접근|회원은 자신의 천장 상태, 재화 계획, 시뮬레이션 기록만 조회, 수정, 삭제할 수 있다. 다른 회원의 데이터에는 접근할 수 없고, 관리자도 회원의 재화 계획과 기록을 확인할 수 없다.|NEEDS_11, NEEDS_12, NEEDS_13|Sim-009, Plan-015, Plan-016, Stat-001, Stat-002|
|보안|Sec-002|로그인한 회원만 접근 가능|로그인하지 않은 사용자는 기록·통계, 재화 계획 저장, 계정 연동, 내 정보 화면에 접근할 수 없다. 접근하려고 하면 로그인 화면으로 안내한다. 시뮬레이터, 확률 계산, 재화 플래너의 계산은 로그인 없이 사용할 수 있다.|NEEDS_12, NEEDS_13, NEEDS_14, NEEDS_15|User-002, User-003, Plan-015, Stat-002, Link-001|
|보안|Sec-003|관리자 기능 접근 제한|게임 데이터 관리(게임, 배너, 규칙, 정기 수입, 이벤트 보상, 패키지, 이미지)와 데이터 가져오기·자동 갱신·반영은 관리자만 사용할 수 있다. 일반 회원과 비회원은 관리자 화면과 기능에 접근할 수 없다.|NEEDS_16, NEEDS_17, NEEDS_18, NEEDS_19|Admin-001, Admin-002, Admin-003, Admin-004, Admin-005, Admin-006, Admin-007, Admin-008, Admin-009, Admin-010|
|보안|Sec-004|비밀번호 해시 저장|비밀번호는 원래 값을 저장하지 않고 해시한 값으로 저장한다. 로그인할 때는 입력한 비밀번호를 같은 방식으로 해시하여 저장된 값과 비교한다. 관리자 계정의 비밀번호도 같은 방식으로 저장한다.|NEEDS_15|User-001, User-002, User-005|
|보안|Sec-005|입력값 검증|회원가입 항목(회원 아이디, 비밀번호, 회원 이름, 이메일 주소)은 필수 입력과 형식을 확인한다. 시뮬레이터와 확률 계산, 재화 플래너의 입력값도 확인한다. 현재 천장 횟수는 0 이상이고 해당 배너의 천장 횟수보다 작은 값, 재화 수량과 뽑기 횟수는 0 이상의 숫자, 목표 확률은 0보다 크고 100보다 작은 값, 패키지 개수는 구매 횟수 제한 이내여야 한다. 관리자가 입력하는 확률은 0 이상 100 이하, 일정은 시작일이 종료일보다 늦지 않아야 하며, 가져오는 파일과 이미지는 형식이 올바른지 확인한다. 올바르지 않은 값은 처리하지 않고 안내한다.|NEEDS_03, NEEDS_06|User-001, Sim-005, Prob-001, Prob-002, Plan-001, Plan-009, Plan-010, Admin-003, Admin-007, Admin-010|
|보안|Sec-006|게임 계정 인증 정보 미저장|계정 연동 과정에서 입력하거나 사용한 게임 계정 정보(이메일, 인증 코드, 인증 토큰 등)는 데이터베이스, 파일, 기록(로그)에 저장하지 않는다. 연동으로는 보유 재화 수량만 가져와서 사용한다. 확인 필요: 연동을 처리하는 별도 서버를 거치는 구조에서 인증 토큰을 어떻게 다룰지는 설계 단계에서 확정한다.|NEEDS_14|Link-001|

## 3. 사용성

|요구사항분류|요구사항 ID|요구사항명|요구사항 상세|근거|관련 요구사항|
|--|--|--|--|--|--|
|사용성|UI-001|로그인 없이 바로 사용|시뮬레이터, 확률 계산, 재화 플래너는 회원가입이나 로그인 없이 바로 사용할 수 있다. 첫 화면에서 해당 기능으로 바로 이동할 수 있다. 화면 배치와 버튼 위치는 이번 단계에서 정하지 않는다.|NEEDS_11, C2|Sim-001, Prob-001, Plan-001|
|사용성|UI-002|처리 결과 안내|가입, 정보 수정, 재화 계획 저장, 가져오기, 반영, 계정 연동 실패 등의 처리 결과를 사용자가 알 수 있도록 안내한다. 입력 오류가 있으면 어떤 항목이 잘못되었는지 안내한다.|NEEDS_03, NEEDS_06|Sim-005, Plan-001, Plan-015, Admin-007, Link-002|
|사용성|UI-003|삭제 전 확인|회원 탈퇴, 관리자의 데이터 삭제처럼 되돌릴 수 없는 작업은 실행하기 전에 한 번 더 확인을 받는다.|NEEDS_15, NEEDS_16|User-006, Admin-001, Admin-002, Admin-006|
|사용성|UI-004|조회 결과 없음 안내|시뮬레이션 기록, 저장한 재화 계획, 확인할 가져온 내용처럼 보여 줄 결과가 없으면 비어 있다는 것을 안내한다.|NEEDS_12, NEEDS_13|Stat-002, Plan-016, Admin-009|
|사용성|UI-005|무과금 기준 기본 화면|재화 플래너의 기본 화면은 결제하지 않는 기준(무과금)이며, 패키지와 오리지늄을 선택하지 않은 상태로 시작한다. 재화를 관리하는 도구로 소개하고 구매를 권하는 문구는 쓰지 않는다. 패키지는 포함했을 때의 차이를 비교해서 보여 주는 용도로만 사용한다.|NEEDS_10|Plan-012, Plan-013|
|사용성|UI-006|이미지 대체 표시|캐릭터, 배너, 재화의 이미지가 없거나 불러오지 못하면 이름, 등급 같은 내용을 글자로 보여 주고 기본 이미지를 보여 준다. 이미지가 없어도 모든 기능을 사용할 수 있다.|NEEDS_20|Sim-010, Plan-017|
|사용성|UI-007|저작권·비공식 안내|게임 이미지의 저작권이 게임 회사에 있고 이 프로그램이 비공식 팬 프로젝트임을 모든 화면에서 볼 수 있는 위치에 안내한다.|C7|Sim-010, Plan-017, Admin-010|

## 4. 시스템환경

|요구사항분류|요구사항 ID|요구사항명|요구사항 상세|근거|관련 요구사항|
|--|--|--|--|--|--|
|시스템환경|SYS-001|MVC 구조|JSP, Servlet 기반의 MVC 구조에 Service 층을 두어 개발한다. 화면(JSP)은 컨트롤러(Servlet)를 거쳐 서비스, 데이터 접근(DAO), Oracle 데이터베이스 순서로 처리한다. 그래프 표시에는 Chart.js를 사용한다. 그 밖의 특정 프레임워크는 이번 단계에서 정하지 않는다.|C1, C3|전체 기능 요구사항|
|시스템환경|SYS-002|웹 브라우저 이용|웹 브라우저에서 사용할 수 있는 동적 웹 프로그램으로 개발한다. 모바일 화면 지원 여부는 이번 단계에서 정하지 않는다.|C3|전체 기능 요구사항|
|시스템환경|SYS-003|개발 환경|아래 개발 환경에서 개발하고 동작을 확인한다.|C3|-|
|시스템환경|SYS-004|다른 게임 추가 구조|다른 게임은 프로그램 수정 없이 데이터만 넣어서 추가할 수 있도록 개발한다. 프로그램 안에서 특정 게임의 이름으로 동작을 나누는 조건문을 쓰지 않는다. 데이터로 표현할 수 없는 게임별 규칙이 있을 때만 그 규칙을 따로 분리해서 구현한다.|C1, C4|Sim-003, Sim-004, Plan-005, Admin-001, Admin-003, Data-001|
|시스템환경|SYS-005|공개 데이터 가져오기|배너와 이벤트 일정은 공개된 게임 데이터 저장소에서 가져온다. 저장소에 접근할 수 없거나 데이터 형식이 바뀌어 가져오지 못하면 관리자가 파일로 직접 가져올 수 있다. 확인 필요: 한국 서버의 확정 일정을 자동으로 가져올 소스는 아직 정하지 못했다(한국 서버용 공개 데이터 저장소가 오랫동안 갱신되지 않은 것으로 보인다).|NEEDS_18, NEEDS_19|Admin-007, Admin-008, Admin-009|
