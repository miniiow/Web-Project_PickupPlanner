## 1. 설계 원칙

|원칙|내용|근거|
|--|--|--|
|게임별 데이터는 테이블로|재화, 환산 비율, 등급, 확률·천장 규칙, 정기 수입은 모두 `game_id`로 게임과 연결한 데이터로 둔다. 특정 게임 이름으로 코드를 나누지 않는다.|Data-001, SYS-004, C4|
|규칙은 배너에 연결|확률·천장 규칙은 규칙 테이블에 두고 배너가 규칙을 가리킨다. 표준 배너들은 같은 규칙을 공유하고, 콜라보처럼 특수한 배너는 그 배너만의 규칙을 가진다.|Sim-003, Sim-004, Admin-003|
|서버별 일정 분리|배너, 이벤트, 패키지의 일정은 본체와 분리해 서버(한국, 중국)별로 저장하고, 확정/예상 여부를 함께 둔다.|Data-002, Plan-006, Plan-007|
|회원 데이터는 회원에 연결|천장 상태, 재화 계획, 시뮬레이션 기록은 `member_id`로 연결하고 회원 삭제 시 함께 삭제한다(`ON DELETE CASCADE`). 비회원의 천장 상태는 DB에 저장하지 않고 세션에만 둔다.|Data-003, Data-004, Sec-001|
|가져온 내용은 대기 테이블에|자동으로 가져온 내용은 본 테이블에 바로 넣지 않고 가져오기 대기 테이블에 두었다가 관리자가 반영한다.|Data-002, Admin-008, Admin-009|
|삭제 대신 비활성|관리자가 만드는 기준 데이터는 `active` 컬럼을 두고, 연결된 데이터가 있으면 삭제하지 않고 비활성으로 바꾼다. 외래키는 삭제를 막는 방식(`RESTRICT`)이다.|기능명세서 관리자 기능 삭제 규칙, UI-003|
|이미지는 경로만|이미지 파일은 서버 폴더에 두고 DB에는 파일 위치만 저장한다. 파일은 공개 저장소에 올리지 않는다.|Data-005, Admin-010|
|게임 계정 정보 미저장|계정 연동에 쓰는 이메일, 인증 코드, 토큰은 어떤 테이블에도 저장하지 않는다. 연동은 별도 테이블이 없다.|Sec-006, Link-001|

### 이름 규칙
- 테이블과 컬럼은 영문 소문자 snake_case, 기본키는 `테이블명_id`로 쓴다. 숫자 기본키는 `NUMBER GENERATED ALWAYS AS IDENTITY`를 쓴다.
- 예/아니오 값은 `CHAR(1)`에 `'Y'`, `'N'`만 허용한다(`CHECK`).
- 일시는 `TIMESTAMP`, 날짜만 필요하면 `DATE`를 쓴다.
