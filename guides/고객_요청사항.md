# 고객 요청사항 - 픽업 플래너
- 제공자 : 개발자(고객 역할)
- 원 요청일 : 2026-11-19
- ID 표기 : NEEDS_01 ~ NEEDS_19
- 사용자 : 가챠 게임을 즐기는 플레이어(회원, 비회원), 게임 정보와 규칙을 관리하는 관리자

## 고객이 해결하고 싶은 문제
>원하는 캐릭터가 나오는 배너까지 재화를 얼마나 모을 수 있는지 따지려면 보유 재화, 정기 수입, 이벤트 보상, 천장 상태를 전부 직접 계산해야 합니다. 그렇게 모은 재화로 실제로 얼마나 기대할 수 있는지도 감으로만 판단하게 됩니다. 실제 게임과 같은 규칙으로 뽑기를 미리 해 보고, 내 재화로 원하는 캐릭터를 얻을 확률이 얼마인지 한곳에서 확인하며 재화를 계획할 수 있으면 좋겠습니다.

## 고객 요청
|ID|고객 요청|
|--|--|
|NEEDS_01|실제 게임의 배너 정보로 1회 뽑기와 10회 뽑기를 해 볼 수 있었으면 좋겠습니다.|
|NEEDS_02|실제 게임의 천장 규칙과 픽업 확률이 그대로 적용되고, 배너 종류에 따라 천장이 이어지는 것도 반영되었으면 좋겠습니다.|
|NEEDS_03|현재 천장 횟수와 픽업 확정 여부를 직접 정해서 그 상태에서 뽑기를 시작할 수 있었으면 좋겠습니다.|
|NEEDS_04|재화와 상관없이 마음껏 뽑아 볼 수도 있고, 내가 입력한 재화만큼만 뽑고 남은 재화를 확인할 수도 있었으면 좋겠습니다.|
|NEEDS_05|현재 천장 상태와 뽑을 수 있는 횟수로 원하는 캐릭터를 얻을 확률을 알 수 있었으면 좋겠습니다. 원하는 확률(예: 90%)로 얻으려면 몇 회가 필요한지도 알고 싶습니다.|
|NEEDS_06|지금 가진 재화를 입력하면 목표 날짜까지 모을 수 있는 재화(정기 수입, 이벤트 보상)를 더해서 몇 번 뽑을 수 있는지 알 수 있었으면 좋겠습니다.|
|NEEDS_07|한국 서버는 중국 서버보다 늦게 운영되므로, 중국 서버의 앞으로의 가챠 일정과 이벤트, 판매 예정 패키지를 한국 서버 일정으로 반영해서 몇 달 뒤의 배너도 미리 계획할 수 있었으면 좋겠습니다.|
|NEEDS_08|재화를 계산할 때 정기 수입, 이벤트 보상, 패키지 중 무엇을 포함할지 내가 고를 수 있었으면 좋겠습니다.|
|NEEDS_09|기간 한정 패키지, 상시 판매 패키지, 금액별로 판매하는 오리지늄을 종류와 개수까지 골라 계산에 넣을 수 있었으면 좋겠습니다. 처음 구매할 때 주는 보너스도 함께 계산되었으면 좋겠습니다.|
|NEEDS_10|기본은 결제하지 않는 기준(무과금)으로 계산하고, 패키지나 오리지늄을 포함하면 뽑기 횟수가 얼마나 늘어나는지 비교해서 볼 수 있었으면 좋겠습니다.|
|NEEDS_11|회원은 천장 상태가 저장되어 다시 접속해도 이어서 쓸 수 있고, 비회원도 브라우저를 닫을 때까지는 천장 상태가 유지되었으면 좋겠습니다.|
|NEEDS_12|회원은 뽑기 시뮬레이션 기록과, 최고 등급이 평균 몇 회 만에 나왔는지, 설정한 확률과 실제 결과가 얼마나 다른지 통계로 볼 수 있었으면 좋겠습니다.|
|NEEDS_13|회원은 재화 계획(목표 배너, 선택한 패키지 등)을 저장해 두고 나중에 다시 볼 수 있었으면 좋겠습니다.|
|NEEDS_14|게임 계정을 연결해서 내 보유 재화를 자동으로 가져올 수 있었으면 좋겠습니다. 계정 연결은 선택 사항이며, 연결하지 않아도 직접 입력해서 모든 기능을 쓸 수 있어야 합니다. 비공식 방법이라 불안정할 수 있다는 점은 미리 알려 주었으면 좋겠습니다.|
|NEEDS_15|회원으로 가입하고 로그인할 수 있고, 내 정보를 확인하거나 수정하고, 원한다면 탈퇴할 수 있었으면 좋겠습니다.|
|NEEDS_16|관리자가 게임과 배너, 배너의 픽업 캐릭터 정보를 등록하고 수정할 수 있었으면 좋겠습니다.|
|NEEDS_17|관리자가 확률과 천장 규칙, 정기 수입, 이벤트 보상, 패키지 정보를 등록하고 수정할 수 있었으면 좋겠습니다.|
|NEEDS_18|관리자가 공개된 게임 데이터를 파일로 한 번에 가져와서 캐릭터와 배너 기본 정보를 채울 수 있었으면 좋겠습니다.|
|NEEDS_19|새로운 배너와 이벤트 일정이 공개되면 사람이 일일이 입력하지 않아도 자동으로 가져와서 최신 상태로 갱신되었으면 좋겠습니다. 가져온 내용은 관리자가 새로 생긴 것과 바뀐 것을 확인한 뒤에 반영할 수 있었으면 좋겠습니다. 자동으로 가져오지 못할 때는 NEEDS_18처럼 직접 가져올 수 있어야 합니다.|

## 공통 개발 조건
|ID|조건|
|--|--|
|C1|여러 게임을 지원하는 MVC 기반 웹 프로그램을 목표로 합니다. 첫 지원 게임은 명일방주(한국 서버 기준)이며, 이후 붕괴: 스타레일, 명조 같은 다른 게임을 추가할 예정입니다.|
|C2|핵심 목표는 가챠 시뮬레이터와 획득 확률 계산, 재화 플래너입니다.|
|C3|JSP, Servlet 기반 동적 화면으로 구성합니다. 특정 프레임워크나 버튼 배치를 지금 필수로 정하지 않습니다.|
|C4|게임마다 다른 내용(재화 종류, 환산 비율, 등급, 천장 규칙, 정기 수입)은 게임별 데이터로 관리하며, 다른 게임은 프로그램 수정 없이 데이터만 넣어서 추가할 수 있어야 합니다.|
|C5|시뮬레이터와 재화 플래너는 계정 연결 없이 동작해야 합니다. 계정 연결은 마지막 확장 단계에서 개발합니다.|
|C6|실제 게임 안에서 뽑기 실행, 결제 기능, 게임 이미지 사용(이름, 등급, 직군만 글자로 표시), 게임 프로그램 코드 분석은 제외합니다.|
